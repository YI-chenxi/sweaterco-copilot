# 给 P2 的主动指令评估样例

以下是待标注语句，不是 P2 的正式评估集，也不代表当前模型已全部通过。建议每例标注 `command_type`、`task_type`、字段、缺失字段、是否允许进入提案，以及需要的上下文。订单号和日期只是示例。

| 语句 | 预期重点 |
| --- | --- |
| 从 2026-11-06 开始每 3 天早上 8 点生成晨报 | 创建定时简报；间隔 3 天；08:00；明确开始日期 |
| Schedule a briefing every day | 创建意图成立；缺当地时间、开始日期 |
| 现在给我一份晨报 | 即时业务请求，不创建定时任务 |
| 把这份晨报改成每天 7 点 | 需唯一简报目标；7 点上午/下午不明，需澄清 |
| 取消刚才那个定时晨报 | 仅在工作区上下文能唯一定位时接受目标 UUID |
| Tell me if ORD-058 has not moved by Thursday | 持续监控；没有明确日期和时间，截止时刻需澄清 |
| Watch ORD058 for no progress by 2026-11-06 18:00; check every hour | 创建监控；订单号规范化；UTC 截止时刻；60 分钟 |
| Watch ODR058 for status DELAYED | 疑似订单号拼错，不静默修正 |
| What is the status of ORD-058 now? | 即时订单查询，不创建监控 |
| 监控 ORD-058 的交期风险 | 当前 V1 没有该监控条件，不擅自映射为已有条件 |
| 好的，确认 | 只有一个明确待确认提案且有可信上下文时才可绑定；多个候选需澄清 |
| 不要确认刚才那个 | 拒绝或澄清，绝不能执行确认 |
| 给 ORD-058 加备注：客户要求周五前回复 | 需新的动作工具契约；当前 P1/P4 V1 不应宣称已执行 |
| 帮我写催办消息 | 草稿与发送动作分开；生成草稿本身不应触发外部发送 |
| Why is ORD-058 at risk? | 事实检索与证据追踪，不是主动任务创建 |

评估时应分别统计：意图分类、字段抽取、缺失/歧义识别、误触发变更、语言表现和上下文目标绑定。尤其要单列“错误地进入确认或写入流程”的严重失败。
